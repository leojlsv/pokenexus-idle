# PokeNexus — Repository Agent Policy

## Authority and precedence

The human project owner is the final authority.

Use this precedence order:

1. explicit instruction from the Human Owner;
2. accepted `docs/architecture/` and `docs/decisions/ADR-*.md`;
3. approved `docs/specs/`;
4. this `AGENTS.md`;
5. assigned canonical role in `docs/agents/`;
6. active READY task in `tasks/active/`;
7. tool-specific adapter/rule.

A lower level may narrow execution but must not contradict a higher level.

## Global execution rules

- Implementation requires a READY task.
- One task has exactly one implementation owner.
- Prefer one task = one branch = one worktree.
- No agent reviews/approves its own implementation.
- Do not broaden task scope silently.
- Do not refactor unrelated code.
- Do not add dependencies without explicit task need/approval.
- Class A changes require an accepted ADR/spec update before implementation.
- P0/P1 QA findings block merge.
- Never claim a command/test passed unless it was actually run.
- Prefer the smallest coherent solution; do not build speculative abstractions.

## Repository hygiene

### No inline changelog/history

Git history, tasks and PRs are the change history.

Do not:
- add change-history comments such as `fixed`, `updated`, `new`, `changed in v2`, dates, author/model names, or previous implementation notes;
- add changelog sections to source files, READMEs or evergreen docs;
- create `CHANGELOG.md`, `CHANGES.md`, `IMPLEMENTATION_SUMMARY.md`, `FIX_SUMMARY.md`, `PROGRESS.md`, `STATUS.md` or similar history/report files unless an explicit task requires a release/report artifact;
- create "handoff", "notes for next agent", or completion-summary files outside the canonical task/QA structure.

Comments explain **why/invariants**, not history.

### No code debris

- No commented-out code.
- No debug logs left in production paths.
- No temporary scripts/files left behind.
- No placeholder/fallback behavior unless specified.
- No silent error swallowing.
- TODO/FIXME must reference a task: `TODO(TASK-123): ...`.
- Remove dead code made obsolete by the task.

### No AI attribution noise

Do not add:
- `Generated by ...`;
- AI model signatures;
- AI co-author footers;
- agent conversation transcripts;
- prompt text inside production files;

unless the Human Owner explicitly requests it.

## Architecture boundaries

### `packages/game-core`
Pure deterministic TypeScript domain logic.
No React, HTTP framework, database client or Cloudflare runtime dependency.
Randomness and time-dependent logic must receive explicit abstractions/inputs.

### `apps/web`
Presentation, input, UX and rendering.
Never authoritative for persistent rewards/progression.
React handles application UI; PixiJS handles realtime 2D rendering where appropriate.

### `apps/api`
HTTP commands, validation and persistence orchestration.
Server remains authoritative for persistent game state.

### `apps/realtime`
Ephemeral HUB/Duo coordination.
Movement/presence must not be continuously persisted.

### `packages/database`
Persistence schema/adapters.
Database concerns must not leak into `game-core`.

## Validation

Expected project-level checks after foundation tooling is installed:

```text
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Run only checks relevant and available for the active task, but report exactly what ran.

## Completion

Use `docs/agents/handoff-protocol.md`.
Completion summaries belong in the agent response/task workflow, not as ad-hoc repository files.
